# Public API Deprecations

This file is the central register for deprecated public UIMD APIs. It applies
to runtime libraries, generated APIs, `.uimd` syntax, the native CLI, MCP
contracts, SDK entry points, and every supported language port.

## Lifecycle

An API enters this register only after the user explicitly decides that it is
obsolete. The change that marks it deprecated must:

1. record the first released version containing the warning;
2. name the supported replacement and provide a concise migration note;
3. retain the old API as a behavior-preserving compatibility adapter;
4. add the native deprecation warning in every affected language port and
   generated/public surface;
5. validate an application generated by the preceding version without editing
   or regeneration.

Removal is automatic and requires no per-API scheduling decision. An API first
deprecated in `0.x.y` remains available in all `0.(x+1).*` releases and is
removed in `0.(x+2).0`. For example, an API deprecated in `0.5.4` remains
available throughout `0.6.*` and is removed in `0.7.0`.

Before an approved middle-number release, audit the active table. Remove every
entry whose two-cycle window has elapsed from all supported ports in the same
change, update migration and compatibility coverage, and move it to the
removed-history table.

## Warning Rules

Prefer native compile-time warnings. When a platform cannot issue one, use its
standard documentation marker. A runtime warning is allowed only when needed,
must identify the replacement, and must be emitted at most once per process so
normal terminal output and test logs are not flooded.

Private implementation details are not public compatibility contracts and do
not enter this register.
